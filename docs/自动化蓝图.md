## 2. 各模块流程图

### ① 预算表生成（纯浏览器，数据不出本机）

```
录入支队信息（手动填表 / 上传院系申报表 xlsx）
        │
        ▼
查票价：优先实时 12306（经 SCF 查价代理，15~30 秒/段）
        │  失败/未勾选 → 用 fares.json 快照（秒出）
        ▼
生成预览 → 下载预算 xlsx（含公式与样式）
        │
        └─▶ 可选：再上传调整后的 xlsx → 生成公文版 Word
```

- 代码：`app.js`（前端）、`tools/rebuild_budget.py` 等（本地批量脚本）、`scf_fare_proxy.js`（查价代理）
- 票价口径：14 天预售窗口逐日取二等座最高价，同城站按官方城市归属过滤

### ② 票价库自动刷新

```
GitHub Actions（每周一 09:00 / 手动 Run workflow / push 触发）
        │
        ▼
python fare_query.py --update fares.json --days 14
        │
        ▼
有变化 → 机器人提交 fares.json + station_codes.json → 推送回仓库
        │
        ▼
GitHub Pages 重新发布 → 网页加载新票价
```

### ③ 决算表 → 打款表

```
上传决算表 docx
        │
        ▼
mammoth.js 浏览器解析表格
        │  提取「院系联合组织」支队，剔除备注含「就协全部」的行
        ▼
预览（支队 / 金额）
        │
        ▼
POST → SCF kdocs_proxy（注入 AirScript-Token）→ AirScript webhook
        │        action = "create"，rows = 解析结果
        ▼
AirScript：在打款表工作簿新建工作表（表头 + 红字斜体示例 + 数据行 + 合计）
        │
        ▼
返回工作表名 → 网页提示成功（另可「下载本地 xlsx 备份」）
```

### ④ 打款表 → 拨付说明（最复杂的一条）

```
在网页选「打款工作表」+ 填「专项名称」
        │
        ▼
第 1 步：POST → SCF → AirScript（打款表）action=export
        │   读取 A~H 列，处理合并单元格（合并区续行继承支队/地点/总金额）
        │   返回 rows[{squad,place,total,amount,cont,dept,leader,cert,proj,projId}] + incomplete[]
        ▼
第 2 步：前端组装
        │   · 识别「自己报销 / 自行报销 / 自付 / 不拨付」→ 弹窗确认后剔除
        │   · 剔除后重算 cont（同一支队第一行 cont=false）
        │   · 编号按「支队」计数（不是按行）
        ▼
第 3 步：docx.js 生成 Word（浏览器本地，不外传）
        │   标题 方正小标宋_GBK 16pt 居中
        │   正文 仿宋 14pt、首行缩进 550 缇、段前 91 缇、行距 303
        │   表格 仿宋_GB2312 7pt 加粗、行高 567 缇、列宽合计 9066 缇
        │   同一支队多院系 → 编号/地点纵向合并；跨页重复表头
        ▼
        自动下载「关于YYYY年X季…经费拨付事宜的说明.docx」
        │
        ▼
第 4 步：POST → SCF（target=note）→ AirScript（拨付说明文件内）
        │   action=syncNote，写入自己所在文件的工作表「YYYY+学期+拨付说明」
        │   · 同表已存在 → 清空 + 取消合并 + 重写
        │   · 不存在 → 新增工作表（文件里只有默认空表时改名复用）
        ▼
第 5 步：POST → SCF → AirScript（打款表）action=cleanupNotes
        │   删掉打款表工作簿里历史遗留的「XX拨付说明」工作表
        ▼
页面显示：Word 已下载 / 说明表已写入 / 清理了哪些旧表
```

## 4. 数据契约（改代码前必读）

### 4.1 打款表列结构（A~H）

| 列 | 含义 | 说明 |
|---|---|---|
| A | 支队 | 含换行：`地点\n院系组合\n日期`；第一行=地点 |
| B | 打款总金额 | 一支队一行；拆院系时**纵向合并** |
| C | 打款院系 | 一支队多院系时每行一个 |
| D | 打款金额 | 本院系金额；空则回退 B |
| E | 项目负责人 | |
| F | 工作证号 | 10 位数字，**按文本处理** |
| G | 项目名称 | |
| H | 项目编号 | 形如 100002042，**必须按文本读**（否则 1E+08） |

- 第 1 行表头；第 2~3 行「例子」示范；第 4 行起正式数据；末行「总计」
- 一个支队拆多个院系时：A、B 列合并，只有合并区首行有值

### 4.2 `export` 返回

```json
{ "sheet": "2026年暑期实践打款院系",
  "rows": [{ "squad":"湖北武汉\n电子系…", "place":"湖北武汉", "total":"14049",
             "amount":"654", "cont":false, "dept":"公共管理学院",
             "leader":"刘近文", "cert":"2019620896", "proj":"研究生社会实践专项经费",
             "projId":"100002089" }],
  "incomplete": [7] }
```
- `cont=true` 表示与上一行同属一个支队（合并区续行，或 A 列文本与上一行完全相同）

### 4.3 `syncNote` 入参

```json
{ "action":"syncNote", "name":"2026暑期拨付说明", "sheetName":"2026暑期拨付说明",
  "separate":false,
  "note": { "title1":"…","title2":"…","body":"…","attach":"…",
            "rows":[[编号,地点,院系,金额,负责人,证号,项目名,项目编号,cont], …],
            "total":"259705" } }
```

### 4.4 命名规则

- 工作表名 / 文件里表名：`{年份}{学期简称}拨付说明`，例 `2026暑期拨付说明`
- 学期解析：工作表名含「寒/暑/春/秋」，暑期在正文中写「暑假」
- Word 文件名：`{标题1}-{标题2}.docx`

## 5. 关键决策与踩坑实录

> 这一节是**最有价值的部分**：以下方案都试过并被否决，别再走一遍。

| # | 方案/问题 | 结果与原因 | 最终做法 |
|---|---|---|---|
| 1 | 用 EdgeOne Pages 做国内镜像 | 部署/额度受限，维护成本高 | 放弃，只保留 GitHub Pages |
| 2 | 让 AirScript 直接生成 Word | 金山无 Word 类型、不能上传 docx | Word 由浏览器 docx.js 生成 |
| 3 | 把说明写进**另一个**金山文件（KSDrive） | 网页调用（脚本令牌）无用户身份，报「用户未登录」；只有编辑器内手动运行才有 | 在目标文件里**各放一份 AirScript**，写自己 |
| 4 | 通过 URL `?target=note` 路由 | 腾讯云**函数 URL 会吞掉查询串** | 改为在**请求体**里带 `target` |
| 5 | 判断代码是否已部署 | 新旧响应太像，无法区分 | 响应头加 `X-Proxy-Version` |
| 6 | 合并单元格的数据读取 | A 列为空的续行被当空行丢弃 → 少院系、金额对不上 | 续行继承支队/地点/总金额；`cont` 标记 |
| 7 | 项目编号 `1E+08` | 数字单元格显示值被科学计数法截断 | 优先 `Value2` 原始值 + 还原整数 |
| 8 | 新建文件时默认空表 | 「只有一张表就改名」逻辑会**顶掉其它学期** | 仅当表名是 `Sheet1/工作表1` 才改名 |
| 9 | 重复写入同一表 | 旧合并区残留导致错位 | 写前 `UnMerge()` + `Clear()` |
| 10 | docx 列宽不生效 | 只设单元格宽度不生效 | Table 上设 `columnWidths` |
| 11 | 表格数字换行 | 7pt 数字在窄列折行 | 加宽证号/金额列（总宽不变）+ 字距 -6 |
| 12 | Word 变 2 页 | 样例下边距为 0，我设了 2.5cm | 页边距照抄样例（下 0） |
| 13 | 字体看起来"变了" | Mac 缺「仿宋_GB2312 / 方正小标宋_GBK」 | 安装字体到 `~/Library/Fonts`；文件本身无问题 |
| 14 | 自己报销的行 | 不该进拨付清单，但会影响总计 | 自动识别 + 弹窗确认剔除 + 提示差额 |

## 6. 运维手册

### 每期操作（3 步）

1. （如需要）网页卡片③：上传决算表 → 在金山新建「打款院系」工作表 → 手工补全院系/负责人/证号/项目编号
2. 网页卡片④：下拉选该期打款表 → 点「📄 生成拨付说明」
3. 检查：Word 是否单页、金山「拨付说明」文件里是否新增该期工作表

### 故障排查矩阵

| 症状 | 原因 | 处理 |
|---|---|---|
| 网页「接口自检」失败 | 令牌过期（180 天） | 金山重新生成脚本令牌 → 更新 SCF 环境变量 |
| 下拉框没有工作表 | AirScript 是旧版（无 list 动作） | 重贴最新 `create_payout_sheet.js` |
| 「未知目标 note」 | SCF 未配 `KDOCS_WEBHOOK_NOTE` | 加环境变量并部署 |
| 写入报「用户未登录」 | 误用了 KSDrive 跨文件 | 改回「文件内各放一份脚本」 |
| 说明表总计 ≠ 打款表总计 | 自己报销行被剔除（预期行为） | 弹窗里可见差额 |
| 说明表少一行院系 | 读到了旧版脚本（无合并支持） | 重贴最新脚本 |
| Word 数字折行 | 字体缺失/列宽 | 装字体；或调 `COLW` |
| 生成的是 2 页 | 页边距被改 | 检查 `margin.bottom = 0` |
| 提交被拒（push） | 机器人自动提交造成分叉 | `git stash -q --include-untracked` → `git pull --rebase` → `stash pop` → push |

## 7. 扩展指南

### 加一个「新的金山文件」作为目标

1. 新建金山表格 → 里面加 AirScript → 粘贴**同一份** `create_payout_sheet.js`
2. 金山里创建脚本令牌，复制 webhook 链接
3. SCF 加环境变量 `KDOCS_WEBHOOK_新名字`（大写）= 链接
4. 网页调用时在请求体加 `target: "新名字"`

> 不需要改 `index.js`，路由是通用的。

### 加一个网页卡片

1. `index.html` 加卡片 + 元素 id（建议前缀区分，如 `note-`）
2. 新建独立 js（如 `note.js`），IIFE 包裹，避免污染全局
3. 底部 `<script src="xxx.js">` 引入
4. 需要云端就复用 `callKdocs(argv, { note: true })` 模式

### 加一个 AirScript 动作

1. 在 `create_payout_sheet.js` 顶部 dispatch 区加
   `if (__action === 'xxx') return __xxx(__argv);`
2. 实现 `function __xxx(argv) { … return 可 JSON 化的值 }`
3. 两端（打款表脚本、说明文件脚本）**贴同一份**，避免版本分叉

## 8. 已知限制

1. **令牌 180 天过期**：到期网页自检会提示，需重新生成并更新 SCF 环境变量
2. **KSDrive 云文档 SDK 只能在编辑器内用**：自动化链路不能跨文件读写，因此「每文件一份脚本」
3. **金山说明表是「表格形态」**：字体/合并/边框都按 Word 版复刻，但**不是** Word 文件；正式报送用下载的 docx
4. **函数 URL 会吞查询串**：所有路由参数走请求体
5. **公开仓库**：任何密钥、学号、身份证号、账号密码都不得进入 `自动化/web`
6. **合并单元格依赖人工规范**：一支队拆院系时请纵向合并 A、B 列（未合并也能识别，但合并更清晰）
